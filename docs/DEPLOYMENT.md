# Развёртывание и данные

Текущий продукт — университетские пространства ADMIN/TEACHER. Сохранение материалов, расписание, готовые фильмы и локальное распознавание не требуют ключа внешней LLM. Создание новых сценариев/голоса требует серверного доступа Google и разрешения университета. Веса распознавания включены в поставку. Устройство рабочего PGlite-развёртывания — в [SERVER.md](SERVER.md).

## Локально

Нужен Node.js 22.12+. Выполните:

```sh
npm ci
cp .env.example .env
npm run dev
```

По умолчанию сервер доступен по `http://localhost:3000`, хранение — `./data`. `START.command` делает такой запуск на Mac и открывает браузер. Для остановки нажмите Control+C и дождитесь завершения.

`SEED_DEMO=true` создаёт вымышленные данные. Переключение на `false` не удаляет уже созданную базу. Для рабочей установки используйте новый каталог и отключённое демо; не очищайте существующие данные без резервной копии.

## Окружение

| Переменная | Назначение |
| --- | --- |
| `HOST`, `PORT` | По умолчанию `127.0.0.1:3000`. За прокси/в контейнере адрес настраивается для окружения. |
| `DATA_DIR` | Постоянная папка локальной БД и закрытых загрузок. |
| `SEED_DEMO` | Для рабочей установки `false`. |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | Оба значения задаются для создания начального администратора новой установки. Пароль: 10–200 символов, буква и цифра. После создания очистите оба значения. |
| `DATABASE_URL` | Необязательно: отдельный PostgreSQL вместо встроенного PGlite. Храните строку подключения как секрет. |
| `NODE_ENV` | В production используется собранный интерфейс и Secure-cookie. |
| `TRUST_PROXY` | Только для известного доверенного reverse proxy; число соответствует фактической схеме проксирования. |
| `GEMINI_API_KEY`, `GEMINI_API_KEY_FILE` | Ключ Google в серверной переменной либо закрытом файле. Без явного пути используется `DATA_DIR/secrets/google-ai.key`; production Compose монтирует отдельный файл в `/run/secrets/google-ai.key`. В клиент ключ не передаётся. |
| `GEMINI_SCRIPT_MODEL` | Сценарий: `gemini-3.8-flash` по умолчанию. |
| `GEMINI_TTS_MODEL`, `GEMINI_TTS_VOICE` | Новая озвучка: `gemini-3.8-flash-tts`, голос `Puck` по умолчанию. Сохранённые WAV и готовые фильмы прежней модели продолжают воспроизводиться. |
| `OPERATIONS_STATUS_FILE` | JSON-состояние серверного копирования для ADMIN. Production: `/run/operations/backup-status.json`, каталог монтируется только для чтения. |

Рабочие секреты задаются частным файлом окружения/хранилищем секретов, не сохраняются в репозитории и не встраиваются в клиент. Существующие аккаунты сохраняются после очистки bootstrap-полей.

Для новой генерации дополнительно требуется явное `settings.allowExternalAI:true` университета. При нажатии «Создать 3D-урок» извлечённый текст источника передаётся Google; озвучка запускается отдельно после проверки сценария. Установка ключа сама по себе не отправляет документы. Ограниченный генератор использует 2–8 глав и пять пространственных шаблонов; длительность определяется готовым аудио, а не фиксированными десятью минутами.

Часовой пояс семестра по умолчанию — Asia/Tashkent; API импорта допускает `timezone`. Параметры сходства локальной модели находятся в `client/src/face.ts`; их изменение требует испытаний, а не только изменения числа.

## Сборка и HTTPS

```sh
npm run typecheck
npm test
npm run build
npm start
```

Production требует HTTPS: cookie `Secure` не будет работать через обычный HTTP. Для локального HTTP используйте режим разработки. Камера работает только в защищённом контексте или на localhost; на другом компьютере в локальной сети нужен HTTPS.

В поставке есть `Dockerfile` и `compose.yaml` с отдельным PostgreSQL и постоянными томами. Перед запуском задайте в частном `.env.deploy` индивидуальные `POSTGRES_PASSWORD`, `ADMIN_EMAIL`, `ADMIN_PASSWORD` и корректный `TRUST_PROXY`. Значения секретов в примерах не фиксируются.

```sh
docker compose --env-file .env.deploy up --build -d
```

После первого входа удалите оба bootstrap-поля и пересоздайте контейнер приложения. Порт Compose привязан к `127.0.0.1:3000`; публикация выполняется через TLS reverse proxy. Пример конфигурации Caddy после замены домена:

```caddyfile
teacher.example.org {
    reverse_proxy 127.0.0.1:3000
}
```

БД не должна публиковаться в интернет. В строке подключения пароль необходимо корректно URL-кодировать. Для нескольких экземпляров приложения нужны общие загрузки, распределённые ограничения запросов и проверка конкурентной работы; один внешний PostgreSQL этого автоматически не обеспечивает.

Факт наличия Compose не означает, что контейнерное окружение и целевая БД уже прошли испытания. Выполненные проверки перечислены в [VALIDATION.md](VALIDATION.md).

## Файлы и модель

- `DATA_DIR/postgres/` — постоянная локальная PostgreSQL PGlite.
- `DATA_DIR/uploads/` — приватные материалы уроков, документы прежних семестров и индивидуальные фото.
- `DATA_DIR/generated/` — WAV новых уроков и данные для повторного использования готового аудио; состояние/сценарии — в таблице `generated_lessons`.
- `client/public/models/face/` → `/models/face/` — веса Human, включаемые в `dist` при сборке.

Проверьте, что reverse proxy отдаёт локальные файлы модели и не подменяет их внешними загрузками. Фото и дескрипторы не являются публичными статическими ресурсами. Камерные кадры аудитории на сервер не отправляются.

Удаление эталона распознавания не обещает физическое стирание всех связанных файлов и резервных копий. Срок хранения в настройках сам по себе не является полной автоматической политикой удаления. До пилота определите хранение биометрии, доступ, ручную альтернативу и порядок удаления из основной базы/копий.

## Резервная копия PGlite

Не запускайте два процесса с одним `DATA_DIR`. Блокировка `server.lock` защищает локальную базу. Не копируйте работающую БД обычным архиватором.

Остановите приложение и создайте копию в новом каталоге **вне** `DATA_DIR`:

```sh
npm run backup -- /absolute/path/to/backups/university-backup
```

Родительская папка назначения должна существовать. Команда копирует базу и загрузки, сохраняет структуру каталогов и манифест SHA256; живой сервер отклоняется. Копия содержит фото, дескрипторы, отметки, хеши паролей, сессии и секреты MFA. Ограничьте доступ и обеспечьте шифрование средствами хранилища.

Восстановление выполняется в новый, ещё не существующий каталог:

```sh
npx tsx scripts/restore.ts /absolute/path/to/backups/university-backup /absolute/path/to/restored-data
```

Команда проверяет размеры/контрольные суммы и не перезаписывает существующий каталог. Задайте восстановленный путь в `DATA_DIR`; проверяйте копию отдельным экземпляром, не подключая его к основному хранилищу.

Рабочий сервер использует `deploy/backup-server.sh`, исполняемый `deploy/recover-backup.sh` для `ExecStopPost`, обновлённый `deploy/start-container.sh` и systemd-пару `ai-teacher-backup.service/timer`: ежедневно в 03:15 Asia/Tashkent, с задержкой до двух минут. Скрипт останавливает контейнер, делает согласованную SHA256-копию, возвращает контейнер и проверяет здоровье; оставляет как минимум 14 проверенных снимков и не удаляет дополнительные снимки моложе 14 дней. Архивы первоначального переноса сохраняются. Копии находятся на том же сервере; внешнее хранилище отдельно не настроено. Состояние/ошибка видны в настройках администратора, без внешних сообщений. Команды управления — в [SERVER.md](SERVER.md).

## Отдельный PostgreSQL

Встроенный файловый бэкап при `DATABASE_URL` не используется. Нужны `pg_dump`/`pg_restore` и согласованная копия загрузок. На время получения согласованной копии остановите запись в приложение. Для Compose:

```sh
docker compose --env-file .env.deploy stop app
docker compose --env-file .env.deploy exec -T db pg_dump -U aiteacher -d aiteacher -Fc > university-backup.dump
```

Отдельно сохраните том загрузок. Восстанавливайте в новую БД, с соответствующим набором файлов, затем проверяйте вход, семестр, фото и проведённую пару. Не выполняйте восстановление поверх рабочей базы без отдельного согласованного плана.

## Перед запуском реальной группы

Проверьте рабочие роли, TOTP, HTTPS, права на файлы/БД, восстановление копии и доступность модели. Проведите реальный пилот распознавания: свет, камера, ракурсы, ложные совпадения/пропуски, задержки и отказ камеры. Согласуйте правила использования фото и ручную альтернативу. Защита от предъявленного фото/видео не реализована; числовое сходство не доказывает личность или точное время прихода.
