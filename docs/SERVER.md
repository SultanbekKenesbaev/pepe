# routemotion.uz

Рабочий адрес: https://routemotion.uz. `www` перенаправляется на основной домен. Входы преподавателя и администратора используют прежние аккаунты.

Урок о производной: https://routemotion.uz/teach?preview=derivative (после входа). Перенесены сценарий, локальная GLB-модель, музыка, эффекты и десять глав готовой озвучки. Длительность — 10:40.064. Просмотр не вызывает внешний AI.

## Расписание просмотра

Для группы ИС-21 / преподавателя Александры Смирновой установлен урок «Производная: смысл и правила» на 21–27 октября 2026 включительно. Каждая запись доступна весь местный день — с 00:00 до 00:00 следующего дня в Asia/Tashkent (24 часа). В кабинете — кнопка «Смотреть урок». Повторный просмотр не создаёт пару или отметки посещаемости.

## Устройство сервера

- Каталог проекта: `/opt/ai-teacher`.
- Выпуски хранятся в `/opt/ai-teacher/releases/<UTC>/ai-teacher`; текущие каталог и тег образа указаны в `release.env`.
- Конфигурация: `compose.production.yaml`, параметры путей в `release.env`.
- Постоянные данные: `/opt/ai-teacher/data`. `DATABASE_URL` не задан; используется перенесённая PGlite 0.3.16.
- Приложение работает от пользователя `node`, с доступной для записи только папкой данных и временными файлами. Порт приложения не опубликован на хосте.
- Существующий Caddy обслуживает HTTPS и проксирует только новый домен через Docker-сеть `app_default`. Данные сертификатов сохранены в существующем постоянном томе Caddy.
- Docker запускается вместе с сервером, контейнер использует `restart: unless-stopped` и проверку `/api/health`.
- Стартовый файл `/opt/ai-teacher/start-container.sh` должен быть доступен пользователю контейнера (`chmod 755`); закрытые административные backup-скрипты остаются `700`, файл ключа — `400` с владельцем UID 1000.
- Команда запуска держит системную блокировку `/data/process.lock`. Этот файл нельзя удалять при работающем приложении; все экземпляры должны запускаться через `deploy/start-container.sh` и `flock`, как в Compose.

## Проверка переноса

До первого старта совпали SHA256 всех 14 таблиц и 137 записей локальной базы. Проверены исходные байты 1051 файла хранилища, включая готовую озвучку. Ключ генерации Google не переносился: для просмотра готового урока он не нужен.

Исходный снимок сохранён в `/opt/ai-teacher/backups/local-storage` и `local-storage.tar.gz`. Это закрытая резервная копия, она не раздаётся сайтом. Результат сверки: `backups/migration-verified.json`. После рабочего запуска дополнительно создана и проверена копия `backups/server-20261020T221420Z` (1052 файла, включая системную блокировку). Настройки Caddy до добавления домена сохранены в `backups/Caddyfile.before-ai-teacher`.

Это копия локальных данных на момент переноса. Дальнейшие записи сайта сохраняются в серверной базе.

## Управление

Команды выполняются на сервере:

```sh
cd /opt/ai-teacher
docker compose --env-file release.env -f compose.production.yaml ps
docker compose --env-file release.env -f compose.production.yaml logs --tail 100 ai-teacher
docker compose --env-file release.env -f compose.production.yaml restart ai-teacher
```

Новая согласованная копия базы, загрузок и озвучки с проверкой SHA256:

```sh
bash /opt/ai-teacher/backup-server.sh
```

Скрипт кратковременно останавливает приложение для согласованного копирования PGlite, создаёт каталог `backups/server-<UTC>`, проверяет SHA256 и снова запускает контейнер с healthcheck. Копия перед расширением — `backups/server-20261020T230218Z` (1052 файла). Первый успешный запуск нового systemd-сервиса создал `backups/server-20261020T231559Z` (1058 файлов); восстановление этого снимка проверено в изолированном контейнере.

Скрипт восстановления `recover-backup.sh` установлен рядом с `backup-server.sh` и вызывается через `ExecStopPost`. Он останавливает только именованный помощник копирования, удаляет текущую непроверенную копию и возвращает приложение. Устаревший `maintenance.lock` удаляется стартовым скриптом только после захвата системной блокировки; `process.lock` никогда не удаляется.

В новом выпуске автоматическое копирование задают `ai-teacher-backup.service` и `ai-teacher-backup.timer` из `deploy/`. Расписание — ежедневно в 03:15 по `Asia/Tashkent`, с задержкой до двух минут и `Persistent=true` для пропущенного запуска. Сохраняются как минимум 14 проверенных снимков; удаляются только дополнительные проверенные снимки старше 14 дней. Исходные архивы переноса не затрагиваются. Копии локальны этому серверу; отдельное внешнее хранилище не настроено.

Состояние атомарно записывается в `/opt/ai-teacher/operations/backup-status.json`. Production Compose монтирует этот каталог только для чтения в `/run/operations`; приложение читает `OPERATIONS_STATUS_FILE=/run/operations/backup-status.json`. Администратор видит последнюю попытку, успех и ошибку в настройках через `/api/operations/status`. Пути/секреты через API не выдаются; внешние уведомления не отправляются. Проверить таймер и журнал:

```sh
systemctl list-timers ai-teacher-backup.timer
systemctl status ai-teacher-backup.service
journalctl -u ai-teacher-backup.service --no-pager -n 50
```

Новая генерация уроков требует серверного ключа Google и `settings.allowExternalAI:true` университета. Production Compose монтирует `/opt/ai-teacher/secrets/google-ai.key` только для чтения в `/run/secrets/google-ai.key` и задаёт `GEMINI_API_KEY_FILE`; локальный резервный путь — `DATA_DIR/secrets/google-ai.key`. По умолчанию: сценарий `gemini-3.8-flash`, озвучка `gemini-2.5-pro-preview-tts` / `Puck`. Оригиналы при загрузке остаются на сервере; текст отправляется Google только при явном создании сценария, озвучка — после проверки и подтверждения. Просмотр готового урока не вызывает провайдера.

Для следующего выпуска создайте новый каталог `releases`, соберите отдельный образ и измените пути/тег в `release.env`. Сохраните `/opt/ai-teacher/data` и действующие конфигурации прокси. Обычный `compose.yaml` из корня проекта создаёт отдельную PostgreSQL и не применяется к этому переносу.
