# Integration API v1

В `progress` дополнительно доступны `phase`, приблизительный `percent`, `stageStartedAt`, `elapsedSeconds`, диапазон `estimatedRemainingSeconds: {min,max}` и при сборке `frames: {completed,total}`. Время указано в секундах. Эти поля необязательны для старых заданий; LLM-этапы показывают достигнутый рубеж без имитации роста по таймеру. Только `ready` означает 100%. Ошибка содержит безопасные `code`, `message` и при наличии `stage`; произвольные частные журналы не передаются. Подключение и основные маршруты v1 сохранены.

Выпуск `20261022T094404Z` развёрнут 22 октября 2026 года на routemotion.uz. Пройдены 133 серверных проверки, интерфейс администратора и настоящий HTTPS-контур API с сохранением ключа/файла после перезапуска. Генерация нового фильма при этой проверке не запускалась. Подробности — в [VALIDATION.md](VALIDATION.md).

Базовый адрес: `https://routemotion.uz/api/v1`. API создаёт десятиминутные учебные фильмы по теме на русском (`ru`), каракалпакском (`kaa`) или узбекском (`uz`). Документы необязательны. API не создаёт расписание групп или посещаемость. Длительность готового фильма — 600 секунд; время подготовки зависит от очереди и провайдеров.

Публичные описания: `GET /api/v1/docs`, `GET /api/v1/openapi.json` и `GET /api/v1/health`. Остальные маршруты требуют серверного Bearer-ключа. Поля и перечисления ответов сверяйте с OpenAPI опубликованного выпуска.

## Доступ и изоляция

Администратор создаёт интеграцию и её ключ в своём кабинете. Полный ключ показывается один раз. Сохраните его в секретах своего сервера; браузер, мобильный клиент, URL, журнал запросов и открытый репозиторий не подходят для хранения ключа. Сессионная cookie сайта не заменяет Bearer-ключ API.

```http
Authorization: Bearer <server-side-api-key>
```

Все ключи одной интеграции видят её задания и файлы. Две разные интеграции изолированы, даже если принадлежат одному университету. `external_teacher_id` — ваша необязательная строка для связи записей; она не предоставляет права преподавателя и не выбирает университет. `metadata` также не влияет на права доступа. Чужие идентификаторы не открывают файлы, задания, озвучку или видео.

При ротации создайте новый ключ той же интеграции, переключите сервер и отзовите старый. Существующие задания и файлы остаются доступны новому ключу. Отзыв проверяется для каждого нового HTTP-запроса, включая запросы частей видео.

Каждый ответ API содержит `X-Request-Id`. Сохраняйте его для разбора ошибки, не записывая Bearer-ключ. Текущая интеграция, лимиты и расход доступны через `GET /account`.

## Файлы

`POST /files` принимает `multipart/form-data` с одним полем `file`.

```sh
curl --fail-with-body https://routemotion.uz/api/v1/files \
  -H "Authorization: Bearer ${AI_TEACHER_API_KEY}" \
  -F 'file=@lesson-notes.txt'
```

Ответ — объект `{id, object:"file", name, mime, size, sha256, textAvailable, extracted_characters, created_at}`. Используйте возвращённый `id` в `file_ids`. Размер указан в байтах; `sha256` относится к оригинальным байтам файла. Метаданные читаются через `GET /files/{id}`, оригинал — через `GET /files/{id}/content`, также с Bearer-ключом. Оригинал и извлечённый текст хранятся приватно; загруженный файл сам по себе не запускает платную генерацию.

- Форматы: PDF с текстовым слоем, DOCX, TXT и CSV.
- Один файл — до 25 MiB; хранилище одной интеграции — до 500 MiB и 1000 файлов.
- Для задания — до 12 уникальных файлов, суммарно до 50 MiB.
- Извлечённый текст — до 150000 символов на файл; общий канонический источник задания — до 180000 символов. Превышение отклоняется с HTTP 422, без незаметного обрезания текста.
- Скан без извлекаемого текста отклоняется с HTTP 422 и кодом `NO_EXTRACTABLE_TEXT`. OCR не выполняется.

Университет должен разрешить внешнюю AI-обработку. При создании задания тема и извлечённые материалы используются для сценария и постановки; текст озвучки передаётся Google. Не загружайте сведения, которые ваша организация не разрешает передавать этим провайдерам.

## Создание задания

`POST /generations`:

```sh
curl --fail-with-body https://routemotion.uz/api/v1/generations \
  -H "Authorization: Bearer ${AI_TEACHER_API_KEY}" \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: semester-2026-lesson-001' \
  --data '{"topic":"Производная и мгновенная скорость","language":"ru","video_mode":"2d","external_teacher_id":"teacher-42","metadata":{"course":"Математика","semester":1}}'
```

| Поле | Ограничение |
| --- | --- |
| `topic` | Строка, 2–200 символов после удаления пробелов по краям |
| `language` | `ru`, `kaa` или `uz` |
| `video_mode` | Необязательно: `2d` (по умолчанию) или `3d`; формат сохраняется в истории и при повторах |
| `file_ids` | Необязательный массив, 0–12 уникальных идентификаторов этой интеграции |
| `external_teacher_id` | Необязательная строка, 1–200 символов; только ваша связь записей |
| `metadata` | Необязательный объект: до 20 ключей длиной до 64 символов; значения — строка до 500 символов, конечное число, boolean или null; весь JSON до 4096 байт |

Ответ HTTP 202 означает, что задание принято, а не что фильм готов. Объект задания содержит `id`, `object:"generation"`, `revision`, `status`, `stage`, `created_at`, `updated_at`, `topic`, `language`, `video_mode`, `duration_seconds:600` и `progress`; при наличии результата или ошибки — `video` или `error`. `progress` отражает сохранённый этап и его счётчики, не обещанное время окончания.

После HTTP 202 сохраните `id`. Проверяйте `GET /generations/{id}` с разумным интервалом, например раз в 5–10 секунд. Готовый результат имеет `status:"ready"`; `failed` требует разбора ошибки и явного повтора. Новые задания продолжаются после озвучки автоматически, без подтверждения голоса. `language_review` сохранён для совместимости со старыми записями. Другие незавершённые состояния не означают готовность видео.

## Идемпотентность и повтор

Заголовок `Idempotency-Key` обязателен для создания, повтора и подтверждения языка: 8–128 символов из `A–Z`, `a–z`, `0–9`, `_`, `-`. Регистр учитывается. Ключ действует в пределах интеграции, метода и маршрута.

При сетевой ошибке повторяйте тот же запрос с тем же ключом. Каноническое содержимое JSON, включая вложенный `metadata`, сравнивается по хешу; перестановка ключей объекта не создаёт другое задание. Порядок массивов сохраняется. Тот же ключ с другим содержимым возвращает HTTP 409 `IDEMPOTENCY_CONFLICT`.

Повтор успешно принятой операции возвращает **текущее** состояние того же задания с HTTP 200 или 202, а не неизменный снимок первого ответа. Он не создаёт второе задание и не запускает повторную платную работу. Если ошибка принятия операции retry/approval уже сохранена, тот же ключ возвращает сохранённую ошибку. Сопоставления сохраняются после перезапуска сервера.

Для явного повтора неготового задания после ошибки используйте `POST /generations/{id}/retry` с новым ключом и текущей версией:

```http
POST /api/v1/generations/<generation-id>/retry
Authorization: Bearer <server-side-api-key>
Idempotency-Key: semester-2026-lesson-001-retry-1
Content-Type: application/json

{"revision":12}
```

Новый запрос с устаревшей `revision` получает HTTP 409. Повтор уже принятого запроса с прежним ключом и тем же телом возвращает текущее задание, даже если его версия успела измениться. Не создавайте новые ключи автоматически при каждом сетевом таймауте.

## Язык и автоматическая сборка

`language` принимает `ru`, `kaa` или `uz`. Сценарий, голос и подписи используют выбранный язык; узбекский сценарий создаётся латиницей. Озвучка для всех языков использует текущую общую модель Google AI Studio и Puck. После проверки числовой длительности система сразу создаёт выбранные 2D- или 3D-сцены и собирает фильм — подтверждать голос не нужно.

Старые ожидающие `language_review` задания автоматически продолжаются после обновления сервиса при активном владельце и разрешённой AI-обработке. Совместимый маршрут `POST /generations/{id}/language-approval` с текущей `revision` и `Idempotency-Key` сохранён только для старых заданий; новые интеграции не должны вызывать его в обычном процессе. Это продолжение существующей попытки, оно не расходует вторую дневную квоту; ограничения параллельной обработки сохраняются. Готовые и неудавшиеся задания автоматически не перезапускаются.

## Список и готовое видео

`GET /generations?limit=20` возвращает `{object:"list", data, has_more, next_cursor}`. `limit` — целое 1–100, по умолчанию 20. Для следующей страницы передайте полученный `next_cursor` как `cursor`; это идентификатор задания, а не номер страницы. Список ограничен текущей интеграцией.

Готовый фильм читается через `GET /generations/{id}/video`. Поля `video.url` и `language_review.chapters[].audio_url` содержат путь относительно origin сервиса: например, `new URL(job.video.url, "https://routemotion.uz")`. Нужен Bearer-ключ; поддерживаются HTTP Range для перемотки и продолжения скачивания, а также HEAD. Истечение показа в интерфейсе не удаляет результат из истории интеграции.

```sh
curl --fail-with-body "https://routemotion.uz/api/v1/generations/${GENERATION_ID}/video" \
  -H "Authorization: Bearer ${AI_TEACHER_API_KEY}" \
  -H 'Range: bytes=0-1023' \
  -o first-kib.bin
```

В браузере воспроизводите видео через защищённый маршрут **своего сервера**: он проверяет доступ вашего пользователя, добавляет Bearer-ключ и передаёт `Range`, `Content-Range`, длину и тип ответа. Обычный `<video src>` не добавляет произвольный Authorization-заголовок. Не переносите ключ в query-параметр или JavaScript браузера.

## Лимиты и ошибки

Администратор настраивает лимиты интеграции: `requestsPerMinute` — 1–600 (по умолчанию 30), `maxConcurrentJobs` — 1–4 (по умолчанию 1), `jobsPerDay` — 1–1000 (по умолчанию 10). Дневной бюджет считается по UTC и включает принятые попытки создания и явного повтора; идемпотентный replay и подтверждение языка не являются новыми попытками. `usage.jobsToday` считает попытки, `usage.totalJobs` — новые задания. После HTTP 429 учитывайте `Retry-After`, если он присутствует.

Ошибки имеют один формат, включая ошибки разбора JSON, загрузки файла и авторизации:

```json
{"error":{"code":"IDEMPOTENCY_CONFLICT","message":"...","request_id":"...","retryable":false}}
```

Может присутствовать безопасное поле `details`. `error.request_id` соответствует `X-Request-Id`. Сообщение предназначено человеку; ветвление программы делайте по коду. Не повторяйте ошибки валидации, отозванного ключа или конфликта идемпотентности бесконечно. Для изменения запроса сначала исправьте данные, затем создайте новый ключ операции.

## Webhook

Настройка доступна только администратору через сессионный кабинет, не через Bearer API:

```http
POST /api/integrations/<integration-id>/webhook
Content-Type: application/json
X-CSRF-Token: <session-csrf-token>

{"url":"https://your-server.example/ai-teacher/events"}
```

Ответ содержит `{webhook:{url,configured},signingSecret?}`. Секрет подписи показывается один раз; храните его отдельно от Bearer-ключа. `{"url":null}` отключает отправку. Разрешён публичный HTTPS-адрес; приватные, loopback и link-local адреса отклоняются, DNS проверяется при отправке и привязывается к соединению. Перенаправления не выполняются. URL из `metadata` не является callback-адресом.

События: `generation.ready`, `generation.failed`, `generation.language_review`. Тело — `{id,type,created_at,data:<public-generation-object>}`. Заголовки:

```http
X-Routemotion-Event-Id: evt_...
X-Routemotion-Signature: t=<unix-seconds>,v1=<hex-hmac-sha256>
```

Подпись считается по `t + "." + rawBody`. Проверяйте сырые байты **до** разбора JSON, допустимое отклонение времени — 5 минут. Пример Node.js для проверки подписи:

```js
import { createHmac, timingSafeEqual } from 'node:crypto';

export function verifySignature(rawBody, header, secret) {
  if (!Buffer.isBuffer(rawBody) || typeof header !== 'string') return false;
  const match = /^t=(\d{1,12}),v1=([a-f0-9]{64})$/.exec(header);
  if (!match) return false;
  const timestamp = Number(match[1]);
  if (!Number.isSafeInteger(timestamp) || Math.abs(Date.now() / 1000 - timestamp) > 300) return false;
  const expected = createHmac('sha256', secret).update(match[1] + '.').update(rawBody).digest();
  return timingSafeEqual(expected, Buffer.from(match[2], 'hex'));
}
```

После проверки подписи разберите событие, сопоставьте `body.id` с `X-Routemotion-Event-Id` и атомарно сохраните ID в своей постоянной базе для дедупликации. Быстро верните успешный HTTP-ответ после надёжного сохранения; долгую обработку выполняйте отдельно. Не считайте порядок доставки гарантированным: при необходимости запросите актуальное задание через API.

Доставка — как минимум один раз, с долговечным outbox и ограничением до 8 попыток; задержка увеличивается от 30 секунд до 6 часов. Повторные события возможны. Событие связано с текущей версией URL и секрета; после смены настройки старое событие не отправляется на новый адрес с новым секретом. Если доставка исчерпана или webhook отключён, состояние задания доступно через API.

## Проверка интеграции

Независимый [HTTP-набор](../tests/integration-contract.test.ts) прошёл 15 сценариев с изолированной постоянной БД и синтетическими провайдерами: Bearer/отзыв, две интеграции одного университета и чужой университет, конкурентная идемпотентность и конфликт содержимого, приватность файлов/аудио/видео, GET/HEAD/Range/416, размеры документов и квоты, перезапуск и повтор без новой работы. Проверены 150000/150001 символов, превышение 25 MiB, общий источник, дневная граница UTC и продолжение каракалпакского задания при дневном лимите 1 с обязательной проверкой свободного слота. Отдельная фикстура воспроизводит остановку между фиксацией задания и запуском генератора: после перезапуска задание видно как failed, replay не запускает работу, явный retry сохраняет тот же ID. Для проверки квот 500 MiB/1000 файлов используются явно отмеченные учётные фикстуры; большие оригиналы не создаются.

Ещё шесть [проверок безопасности](../tests/integration-security-contract.test.ts) покрывают канонический JSON, запрещённые IP/URL, HMAC по исходным байтам и защищённое хранилище подписей. [Webhook-набор](../tests/integration-webhooks.test.ts) отдельно проверяет долговечную доставку, повторы, ротацию и перезапуск через локального получателя с тестовым транспортом, без обращения к внешним адресам.

Запуск из корня проекта:

```sh
node_modules/.bin/tsx --test tests/integration-contract.test.ts tests/integration-security-contract.test.ts tests/integration-webhooks.test.ts
```

Такие тесты не вызывают Google/Codex и не доказывают качество нового фильма. Действительный сквозной прогон с провайдерами и production-проверка фиксируются отдельно в [VALIDATION.md](VALIDATION.md).

## Отдельные форматы и очереди

Новые запросы без `video_mode` создают `2d`. Форматы используют разные брокеры и постоянные очереди; долгая 3D-постановка не удерживает 2D-задание. Обращения к общему Google-голосу выполняются последовательно по одной реплике для соблюдения квоты. `GET /account` сообщает `video_modes` и `default_video_mode`. Старые задания без сохранённого формата остаются `3d`; повтор запускает тот же формат. Смена `video_mode` с уже использованным `Idempotency-Key` возвращает 409; для другого формата создайте новое задание с новым ключом.
