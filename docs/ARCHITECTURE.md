# Архитектура университетского приложения

Документ описывает текущий университетский объём. Доступны две роли: ADMIN и TEACHER. Старые модели сохранены для миграции исторических данных; они не являются обещанием функций нового интерфейса.

## Компоненты

```text
React + TypeScript / Vite
  /teach                  Сегодня · Уроки · Посещаемость
  /admin/:page?           Университетская база и аналитика посещаемости
  /account               Пароль и TOTP
  face.ts                Локальный Human v3 / WebGL, запасной CPU
         │ same-origin API, cookie + CSRF
Express 5 + TypeScript
  auth / access / crud / university / files
  lesson-materials / document-text / attendance-analytics
         ├─ PostgreSQL: дисковый PGlite или pg Pool / DATABASE_URL
         └─ DATA_DIR/uploads: закрытые фото и документы
```

Преподаватель загружает название урока, дисциплину и документы. Сервер сохраняет оригиналы и локально извлечённый текст; группы и расписание не требуются. Генерация видео из новых загрузок пока не выполняется. Прежний API семестров отдельно сохраняет разбор тем и предложенного недельного времени правилами.

Подготовленный 3D-урок о производной воспроизводит готовую озвучку Google и синхронную Three.js-графику. Голос создаётся отдельным серверным скриптом; просмотр не вызывает платные API. См. [CINEMA.md](CINEMA.md).

## База

| Таблица | Назначение |
| --- | --- |
| `schema_migrations` | Версии схемы/миграции. |
| `institutions` | Университет и настройки в JSONB. |
| `users` | Уникальная почта, университет, хеш пароля, профиль/роль, секрет TOTP. |
| `auth_sessions` | Хеш cookie-токена, пользователь, CSRF, срок сессии, незавершённое подключение TOTP. |
| `entities` | Типизированные JSONB-карточки групп, студентов, дисциплин и аудиторий. Индекс университет + вид. |
| `semesters` | Университет, преподаватель, архивный флаг и JSONB с файлами, темами, группами, датами и недельным расписанием. |
| `lesson_materials` | Университет, автор, FK дисциплины и JSONB с названием урока, `status:'stored'`, файлами и извлечёнными текстами. Индекс университет + преподаватель. |
| `teaching_sessions` | Событие расписания, университет/преподаватель, `revision`, JSONB состояния пары, снимка состава, отметок и сканирований. Частичный уникальный индекс запрещает две активные пары одного события; индекс университет + дата события + преподаватель обслуживает аналитику. |
| `face_enrollments` | Эталон студента: дескриптор, версия модели, ссылка на фото, время. FK на студента с каскадным удалением записи эталона. |
| `files` | Университет, владелец, имя, MIME, размер и внутренний путь защищённого файла. |
| `audit` | Входы и важные изменения с исполнителем и временем. |

Часть технических таблиц предыдущего варианта остаётся для сохранения истории. Их наличие не включает прежние учебные сценарии в новый продукт.

JSONB проверяется Zod. Связи студента/группы, дисциплины/семестра, аудиторий и файлов проверяются сервером по университету; ссылки внутри JSONB не являются отдельными SQL FK. При занятии сохраняется снимок события и состава посещаемости с именами. Изменение семестра, перевод и переименование студента не переписывают этот снимок. Дисциплину, используемую загруженными уроками, удалить нельзя.

Группа содержит `teacherIds`: несколько преподавателей могут работать с одной группой. Совместимость с прежним `teacherId` сохранена. Сервер вычисляет группы преподавателя по этим назначениям и назначенному расписанию; изменение групп одного преподавателя сохраняет назначения остальных.

## Доступ

| Операция | ADMIN | TEACHER |
| --- | --- | --- |
| База групп/студентов/дисциплин/аудиторий, аккаунты | Управление своим университетом | Только разрешённое чтение; базу студентов не изменяет |
| Фото и эталон лица | Добавление/удаление | Чтение эталонов назначенных групп для проверки |
| Загруженные уроки и оригиналы | Записи своего университета | Только собственные; назначенные группы не требуются |
| Семестры | Все семестры своего университета | Свои семестры и назначенные группы |
| Пары и посещаемость | Все группы своего университета | Собственные активные пары в разрешённых группах; завершённая собственная история сохраняется после переназначения группы |
| Аналитика посещаемости | Все сохранённые пары своего университета | Только пары со своим `teacherId` |
| Проверка спорных отметок | Да | Для своих пар |

Каждый защищённый запрос проверяет сессию, роль и университет. Подмена `institutionId` не открывает другой университет. Видимость кнопок не заменяет серверную проверку. Активные аккаунты иных ролей не принимаются новым входом.

## Загрузка урока

`POST /api/lesson-materials` принимает `title`, `subjectId`, 1–12 `files` и необязательный `institutionId`. Дисциплина должна существовать в своём университете. Поддерживаются PDF/DOCX/TXT/CSV, до 25 МБ на файл и 50 МБ на запрос; извлечённый текст ограничен 200 000 символами на документ и 1 000 000 на урок. TXT/CSV читаются как UTF-8.

Все документы проверяются до записи. Корректный PDF-скан без текста сохраняется с пустым текстом и нулём извлечённых символов; OCR нет. PDF действительно разбирается парсером с `stopAtErrors:true`, служебные номера страниц не считаются текстом. Повреждённые документы и пустые текстовые файлы отклоняются.

Исходные байты записываются под случайными именами с закрытыми правами в `DATA_DIR/uploads`. Метаданные попадают в `files`, текст и связи — в JSONB `lesson_materials` одной транзакцией. При ошибке записи файлы удаляются. Бэкап должен сохранять и БД, и каталог загрузок. `GET /api/lesson-materials` возвращает метаданные без текста; `GET /api/lesson-materials/:id` — также `documents:[{fileId,text}]`. Исходники выдаются через `/api/files/:id` владельцу или администратору своего университета, без обхода через ссылки старой общей библиотеки.

Урок получает статус `stored`. Он не создаёт семестр, расписание или сгенерированное видео. Автоматическая подготовка 3D из этих источников — следующий этап разработки.

## Прежние семестры и проведение пары

Семестры и существующие расписания сохранены; новый интерфейс преподавателя не требует этого импорта для загрузки уроков. Совместимый API работает так:

1. Импорт до 12 документов: до 25 МБ на файл и 50 МБ суммарно. PDF должен содержать извлекаемый текст; встроенного OCR нет.
2. Возвращается `draft` с настоящими темами/файлами и найденными недельными слотами. Если время не найдено, оно остаётся пустым.
3. `ready` требует тем и хотя бы одного слота; даты, группы и аудитории проверяются сервером.
4. События выводятся из подтверждённого расписания на выбранную дату. Тема выбирается последовательно по номеру занятия; при исчерпании тем новые темы не выдумываются. Часовой пояс по умолчанию — Asia/Tashkent.
5. Начало создаёт `live`; повторное начало активного события возвращает существующую пару. Далее доступны `paused → live` и `live/paused → completed`. Время паузы исключается из активного таймера.
6. Изменения выполняются с версией `revision`; устаревшая версия возвращает 409. Сохранение использует сравнение версии в SQL. Клиент обновляет состояние при конфликте.

Удаление семестра, который уже использовался, архивирует его, сохраняя проведённые пары.

## Камера и посещаемость

`face.ts` загружает локальные модели Human v3 с `/models/face/`. Эталон: одно лицо на JPG/PNG/WEBP, фото до 10 МБ и не меньше 120×120; вычисляется 1024-мерный дескриптор `human-v3-face-description-1024`. Фото передаётся только на собственный сервер приложения. Дескрипторы хранятся в БД, веса модели включены в поставку.

Для пары планируется пять проверок: первая на 120-й секунде активного времени, остальные — на 25%, 50%, 75% и 95% оставшегося после первых двух минут интервала. Браузер включает камеру, выполняет локальное сопоставление и останавливает поток. Проверки не выполняются во время паузы. При ошибке требуется исправление/повтор; пять успешных результатов не гарантируются автоматически.

Сопоставление использует порог сходства 0.65 и отрыв от второго кандидата 0.08; дубли и неоднозначные лица остаются неопределёнными. Это параметры алгоритма, а не подтверждённая точность. Исходные кадры аудитории не отправляются и не сохраняются. На сервер уходят метаданные проверки; сервер проверяет группу, наличие эталона, пределы чисел, время и версию. Он не повторяет распознавание по изображению и не доказывает подлинность клиентского кадра.

Все студенты начинают с `unconfirmed`. Совпадение даёт `present` либо `late` при первом обнаружении значительно позже начала; интерфейс описывает это как «замечен позже», а не доказанное опоздание. Сохраняется самое раннее `firstSeenAt`. Пустой/неуспешный кадр не означает отсутствие. `absent` и другие спорные статусы подтверждаются вручную; ручные решения не перезаписываются последующими сканированиями.

`GET /api/attendance/analytics` собирает сохранённые `teaching_sessions` за включительный период `from`–`to`: по умолчанию 14 дней до сегодняшней даты университета, максимум 366. Возможны фильтры группы и преподавателя; сервер ограничивает университет и для TEACHER всегда собственный `teacherId`. Возвращаются сводка, все дни периода, группы с занятиями и сами пары. Включены активные, приостановленные и завершённые пары, с отдельными счётчиками состояния.

Расчёт использует отметки «студент × занятие», а не текущий состав группы. `attendanceRate = 100 × (present + late) / (present + late + absent)`; `confirmationRate = 100 × (total − unconfirmed) / total`. Значения округляются до одного знака, нулевой знаменатель даёт `null`. `excused` и `unconfirmed` исключены из знаменателя посещаемости; завершение пары не превращает неизвестный статус в отсутствие. Аналитика только читает сохранённые записи, не изменяя их историю.

Потоки определения возраста/пола и эмоций отключены; извлекается только лицевой дескриптор. Предполагаемая внимательность не оценивается. Проверок живого лица и защиты от предъявленного фото нет. Реальная групповая съёмка, освещение, перекрытия и ложные совпадения требуют пилотных испытаний.

## Защита и эксплуатация

Есть scrypt, случайные серверные cookie-сессии, HttpOnly/SameSite, Secure в production, CSRF, ограничения запросов, TOTP, отзыв сессий и параметризованные SQL-запросы. Файлы закрыты авторизацией, ограничены размером/форматом; используются `nosniff` и CSP. Это не заменяет антивирус, аудит развёртывания и защиту хранилища.

Локальный PGlite рассчитан на один процесс с блокировкой `DATA_DIR`. Для отдельного PostgreSQL предусмотрен pg Pool; несколько серверных экземпляров требуют общего файлового хранилища, распределённых лимитов и испытаний. Бэкап должен включать БД и загрузки, содержащие в том числе биометрические эталоны и секреты MFA.

Срок хранения в настройках сам по себе не удаляет автоматически все фото, эталоны и историю новых пар. Полная политика удаления/архивов и юридическое основание биометрии определяются до пилота. Автотесты и локальная демонстрация не подтверждают промышленную нагрузку или пригодность распознавания для реальной аудитории.
